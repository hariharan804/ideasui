# MDX Documentation Rules

This document defines the guidelines and requirements for creating and maintaining MDX documentation pages within `apps/docs`.

---

## 📁 File Location & Naming Conventions

- **Path:** `apps/docs/content/react/components/(category)/[component-name].mdx`
- **File Name:** kebab-case matching the component package name (e.g. `checkbox.mdx`, `input-field.mdx`).
- **Showcase Path:** `apps/docs/showcase/[component-name]/[demo-name].tsx`

---

## 📝 Frontmatter Structure

Every component MDX file must begin with valid YAML frontmatter containing metadata and external links:

```yaml
---
title: Checkbox
description: An accessible, theme-aware compound checkbox primitive supporting standalone usage, controlled state, custom icons, grouped selection trees, indeterminate state, visual variants, and WCAG 2.1 AA compliance.
links:
  npm: true
  rac: https://react-spectrum.adobe.com/react-aria/Checkbox.html
  source: checkbox/src/checkbox.tsx
  recipe: core/theme/src/recipes/checkbox/checkbox.ts
  storybook: Components/Checkbox
---
```

---

## 🏗️ Standard Section Hierarchy

MDX pages must follow a consistent section structure:

1. **`<QuickNav />`**: Top anchor navigation block listing all major `##` headers on the page.
2. **`## Installation`**: `<InstallTabs pkg="@ideasui/[component-name]" />` component.
3. **`## Import`**: Code block showing imports from both `@ideasui/react` barrel and individual package `@ideasui/[component-name]`.
4. **`## Basic Usage`**: Shorthand / default usage with `<Preview name="[component]-basic" />`.
5. **Feature Sections**:
   - `## Variants & Color Schemes`
   - `## Sizes`
   - `## Corner Shapes (Radius)`
   - `## States & Validation`
   - `## Controlled State`
   - `## Custom Icons` / Feature Specifics
   - `## [Component] Group` (if compound composition)
6. **`## Standalone CSS`**: BEM classes, slot target selectors, and `@ideasui/styles` usage.
7. **`## API Reference`**: Must use `<APIReferenceViewer componentName="[camelCaseName]" />`.

---

## 🖼️ Live Previews & Showcase Demos (`<Preview />`)

- **Rule 1:** DO NOT embed interactive React components directly in MDX body text.
- **Rule 2:** Use `<Preview name="[component]-[demo]" />` for live interactive component previews.
- **Rule 3:** Create demo components in `apps/docs/showcase/[component-name]/[demo-name].tsx`.
- **Rule 4:** Export all demos in `apps/docs/showcase/[component-name]/index.ts`.
- **Rule 5:** Register all demos in `apps/docs/showcase/index.ts` under `demos` dictionary.

````
## 🎨 Standalone CSS & BEM CSS Classes

Every component MDX file MUST include a `## Standalone CSS` section explaining non-Tailwind usage via `@ideasui/styles`, followed by a `### BEM CSS Classes` subsection.

### Rules & Template:

1. **Package Installation**: Show how to install `@ideasui/styles`.
2. **Stylesheet Imports**: Show importing `@ideasui/styles/base.css` + `@ideasui/styles/components/[component-name].css` or `@ideasui/styles`.
3. **BEM Element & Slot Mapping**: List all namespaced BEM class names and corresponding `data-slot` attributes.
4. **BEM Modifiers**: Document visual variant, size, and state modifier classes (`--solid`, `--outline`, `--sm`, `--md`, `--lg`, `--disabled`, `--invalid`, `--focused`).

```markdown
## Standalone CSS

`Checkbox` can also be used in non-Tailwind projects via the pre-compiled `@ideasui/styles` package.

Install the standalone styles package:

```bash
pnpm add @ideasui/styles
````

Import base tokens and the component stylesheet:

```tsx
import '@ideasui/styles/base.css';
import '@ideasui/styles/components/checkbox.css';
```

Or import all component styles in a single bundle:

```tsx
import '@ideasui/styles';
```

### BEM CSS Classes

`Checkbox` components expose standard BEM class names and granular slot target selectors generated by the `@ideasui/theme` recipe:

- **Block / Root:** `.ideasui-checkbox` (`root` slot) — Main label wrapper element.
- **Elements (Slots):**
  - `.ideasui-checkbox__input` (`input` slot) — Hidden native `<input type="checkbox">` element.
  - `.ideasui-checkbox__indicator` (`indicator` slot) — Custom visual checkbox square/circle indicator.
  - `.ideasui-checkbox__icon` (`icon` slot) — Check or indeterminate icon inside indicator.
  - `.ideasui-checkbox__label-text` (`labelText` slot) — Visible label text element.
- **Group Elements:**
  - `.ideasui-checkbox-group` (`checkbox-group` slot) — Group `<fieldset>` wrapper.
  - `.ideasui-checkbox-group__label` (`checkbox-group-label` slot) — Group label element.
  - `.ideasui-checkbox-group__description` (`checkbox-group-description` slot) — Group description text.
  - `.ideasui-checkbox-group__error` (`checkbox-group-error` slot) — Validation error alert text.
- **BEM Modifiers:**
  - **Visual Variants:** `.ideasui-checkbox--solid`, `.ideasui-checkbox--outline`, `.ideasui-checkbox--subtle`
  - **Sizes:** `.ideasui-checkbox--sm`, `.ideasui-checkbox--md`, `.ideasui-checkbox--lg`
  - **Radius Shapes:** `.ideasui-checkbox--radius-none`, `.ideasui-checkbox--radius-full`
  - **States:** `.ideasui-checkbox--selected`, `.ideasui-checkbox--indeterminate`, `.ideasui-checkbox--disabled`, `.ideasui-checkbox--invalid`

## 📊 API Reference & Metadata Viewer (`<APIReferenceViewer />`)

- **Rule 1:** DO NOT write manual HTML or Markdown tables for prop definitions in MDX files.
- **Rule 2:** Always render `<APIReferenceViewer componentName="[camelCaseName]" />` under `## API Reference`.
- **Rule 3:** Register the component's TypeScript prop metadata in `apps/docs/lib/docs/components-props.ts`:
  1. Add `[camelCaseName]: ComponentDoc[];` to `PropsDocumentation` interface.
  2. Add array of `ComponentDoc` items to `propsDocumentation.[camelCaseName]`.

---

## ♿ Accessibility & Code Quality

- Include JSDoc descriptions and default values for all props in `components-props.ts`.
- Code snippets must use standard TypeScript/React syntax highlighting (` ```tsx `).
- Previews must pass WCAG 2.1 AA accessibility checks.
