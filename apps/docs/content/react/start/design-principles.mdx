IdeasUI is designed around a few core principles that keep the library accessible, flexible, themeable, and easy to use as applications grow.

---

## Core Principles

### 1. Semantic Intent Over Visual Description

Props and variants should communicate **what an action means**, rather than describing how it should look.

```tsx
import { Button } from '@ideasui/react';

// Primary action
<Button color="primary">Save Changes</Button>

// Alternative action
<Button variant="outline">Edit Details</Button>

// Destructive action
<Button color="danger">Delete Account</Button>
```

Choose variants and colors based on the purpose of the action:

| Variant / Color             | Purpose             | Typical Usage                           |
| --------------------------- | ------------------- | --------------------------------------- |
| **`primary`**               | Main action         | Primary action in a workflow            |
| **`secondary` / `outline`** | Alternative action  | Supporting actions                      |
| **`subtle` / `ghost`**      | Low-emphasis action | Secondary or inline controls            |
| **`danger`**                | Destructive action  | Delete, remove, or irreversible actions |

The goal is to make component usage understandable from the code itself.

---

### 2. Accessibility as a Foundation

IdeasUI uses **React Aria primitives** to provide accessible interaction patterns and behavior.

Components can expose interaction state through data attributes such as:

- `data-hovered`
- `data-pressed`
- `data-focus-visible`
- `data-disabled`
- `data-selected`

React Aria also provides behavior for keyboard interaction, focus management, and ARIA attributes where appropriate.

Accessibility remains part of the component foundation rather than something that needs to be added separately by each application.

---

### 3. Composition Over Configuration

IdeasUI favors composable components over large components with many configuration props.

Components can be combined, reordered, or omitted depending on the application's needs.

```tsx
import { Button, ButtonGroup } from '@ideasui/react';

<ButtonGroup className="gap-3">
  <Button color="primary">Confirm</Button>
  <Button variant="outline">Cancel</Button>
</ButtonGroup>;
```

This keeps components flexible while allowing applications to build their own higher-level UI patterns.

---

### 4. Perceptual OKLCH Theme System

IdeasUI uses **OKLCH** for its color system.

OKLCH provides a perceptual color model that makes it easier to create consistent color scales and theme variations.

```css
:root {
  --ideasui-color-primary: 0.54 0.22 272;
}
```

Semantic tokens then allow components and application UI to consume these colors without depending directly on individual color values.

For example:

```tsx
<div className="bg-surface text-content-primary">Theme-aware content</div>
```

This allows the same UI to work across light and dark themes.

---

### 5. Type Safety & Developer Experience

IdeasUI provides TypeScript types for component props and variants, giving developers autocomplete and compile-time feedback while building interfaces.

```tsx
import { Button } from '@ideasui/react';

<Button
  color="primary"
  size="md"
  onPress={(event) => {
    console.log(event);
  }}
>
  Save
</Button>;
```

Typed component APIs make variants, properties, and event handlers easier to discover directly from the editor.

---

### 6. Separation of Logic and Styling

IdeasUI separates component behavior from its styling and theme system.

- **`@ideasui/react`** — React components and interaction logic.
- **`@ideasui/theme`** — Design tokens, theme configuration, recipes, and Tailwind CSS integration.
- **`@ideasui/styles`** — Pre-compiled CSS for projects that do not use Tailwind CSS.

This allows applications to choose the styling approach that best fits their architecture.

```text
@ideasui/react
      │
      ├── Component behavior
      │
      ├── @ideasui/theme
      │      ├── Design tokens
      │      ├── Theme system
      │      └── Recipes
      │
      └── @ideasui/styles
             └── Pre-compiled CSS
```

---

### 7. Modular Package Architecture

IdeasUI is structured as a modular monorepo.

Applications can use the unified package:

```tsx
import { Button } from '@ideasui/react';
```

Or use standalone component packages when a more granular dependency structure is preferred:

```tsx
import { Button } from '@ideasui/button';
```

This package architecture keeps the library flexible as the component collection grows.

---

### 8. Consistent Customization

IdeasUI provides multiple levels of customization without requiring applications to replace the underlying components.

Start with component props:

```tsx
<Button color="primary" variant="outline">
  Save
</Button>
```

Add local customization with `className`:

```tsx
<Button className="rounded-xl px-6">Save</Button>
```

For reusable application-specific styles, extend the component recipe with `tv()`:

```tsx
const customButton = tv({
  extend: button,
  variants: {
    intent: {
      custom: {
        base: 'rounded-2xl',
      },
    },
  },
});
```

This provides a progression from simple customization to reusable design patterns.
