IdeasUI works naturally with Tailwind CSS. Start with `className` for most customizations, use semantic tokens for theme-aware colors, and reach for BEM classes or `tv()` recipes when you need reusable styling.

---

## Basic Styling

### Using className

Every IdeasUI component accepts a `className` prop.

Use it for one-off layout and visual adjustments:

```tsx
import { Button } from '@ideasui/react';

export function Example() {
  return (
    <Button color="primary" className="rounded-xl px-6 shadow-sm">
      Save Changes
    </Button>
  );
}
```

You can also use responsive utilities and semantic color tokens:

```tsx
<Button className="w-full sm:w-auto">Continue</Button>
```

---

## Semantic Design Tokens

Prefer IdeasUI semantic tokens when customizing colors.

```tsx
<div className="bg-surface text-content-primary border-border-subtle border p-6">
  <h2 className="text-content-primary font-semibold">Account Settings</h2>
  <p className="text-content-secondary text-sm">Manage your account preferences.</p>
</div>
```

This keeps custom styles consistent with the active IdeasUI theme and allows them to work across light and dark modes.

For available tokens, see **[Design Tokens](/react/docs/start/tokens)**.

## BEM Class Architecture

IdeasUI components expose BEM-style class names for their internal structure.

This gives you stable class targets when you need to customize component styles outside of `className`.

### Naming Convention

| Tier     | Format                 | Example         |
| -------- | ---------------------- | --------------- |
| Block    | `.[block]`             | `.btn`          |
| Element  | `.[block]__[element]`  | `.btn__icon`    |
| Modifier | `.[block]--[modifier]` | `.btn--primary` |

For example, a Button may use:

```text
.btn
.btn__icon
.btn__label
.btn__loader
.btn__shortcut
.btn--primary
.btn--solid
.btn--md
```

### Customizing BEM Classes

You can target these classes from your application stylesheet:

```css
.btn.btn--primary {
  letter-spacing: var(--ideasui-tracking-wide);
}

.btn .btn__label {
  font-weight: 600;
}

.btn .btn__icon {
  opacity: 0.9;
}
```

Use BEM selectors when you want a consistent customization to apply to multiple instances of a component.

## State-Based Styling

IdeasUI components expose interaction state through data attributes.

This allows you to style states directly with Tailwind CSS:

```tsx
<Button className="bg-surface-subtle text-content-primary data-[hovered=true]:bg-surface-muted data-[focus-visible=true]:ring-border-focus data-[focus-visible=true]:ring-2 data-[pressed=true]:scale-95">
  Interactive Button
</Button>
```

### Common State Attributes

| Attribute                   | State                                |
| --------------------------- | ------------------------------------ |
| `data-hovered="true"`       | Pointer is hovering the component    |
| `data-pressed="true"`       | Component is currently pressed       |
| `data-focus-visible="true"` | Component has keyboard-visible focus |
| `data-disabled="true"`      | Component is disabled                |
| `data-selected="true"`      | Component is selected                |

You can also target these states with regular CSS:

```css
.btn[data-hovered='true'] {
  background: var(--ideasui-color-surface-muted);
}

.btn[data-pressed='true'] {
  transform: scale(0.96);
}

.btn[data-focus-visible='true'] {
  outline: 2px solid var(--ideasui-color-border-focus);
}
```

## Responsive Styling

Use Tailwind's responsive modifiers directly on component `className` props:

```tsx
import { Button, ButtonGroup } from '@ideasui/react';

<ButtonGroup className="flex-col sm:flex-row">
  <Button className="w-full sm:w-auto">Save</Button>

  <Button variant="outline" className="w-full sm:w-auto">
    Cancel
  </Button>
</ButtonGroup>;
```

No additional IdeasUI configuration is required.

## Extending Component Recipes

When you need a reusable custom style, extend the existing IdeasUI recipe with `tv()`.

This is useful when the same customization appears throughout your application.

```tsx
import { Button as BaseButton, type ButtonProps } from '@ideasui/react';
import { button } from '@ideasui/theme/recipes';
import { tv, type VariantProps } from 'tailwind-variants';

const customButton = tv({
  extend: button,
  slots: {
    base: 'rounded-2xl font-semibold tracking-tight',
  },
  variants: {
    intent: {
      glass: {
        base: 'bg-surface-subtle/60 text-content-primary backdrop-blur-md',
      },
      surface: {
        base: 'border-border-subtle bg-surface text-content-primary border shadow-sm',
      },
    },
  },
  defaultVariants: {
    intent: 'surface',
  },
});

type CustomButtonVariants = VariantProps<typeof customButton>;

interface CustomButtonProps extends Omit<ButtonProps, 'className'>, CustomButtonVariants {
  className?: string;
}

export function CustomButton({ intent, className, ...props }: CustomButtonProps) {
  const styles = customButton({ intent });

  return <BaseButton className={styles.base({ className })} {...props} />;
}
```

The advantage is that your custom component keeps the original IdeasUI recipe while adding your own application-specific variants.

## Inline Styles

Use React's `style` prop when a value needs to be calculated dynamically at runtime.

```tsx
<Button
  style={{
    width: `${progress}%`,
  }}
>
  Uploading
</Button>
```

For static styling, prefer Tailwind utilities or CSS instead.

---

## CSS Modules

CSS Modules are useful when you want locally scoped styles.

```css
/* ActionCard.module.css */

.card {
  background: var(--ideasui-color-surface-subtle);
  border: 1px solid var(--ideasui-color-border-subtle);
  border-radius: 1rem;
  padding: 1.25rem;
}
```

```tsx
import styles from './ActionCard.module.css';
import { Button } from '@ideasui/react';

export function ActionCard() {
  return (
    <div className={styles.card}>
      <Button color="primary">Continue</Button>
    </div>
  );
}
```

---

## CSS-in-JS

IdeasUI components can also be used with CSS-in-JS libraries such as `styled-components`.

```tsx
import styled from 'styled-components';
import { Button } from '@ideasui/react';

const CustomButton = styled(Button)`
  border-radius: 12px;
  font-weight: 600;
`;
```

For most IdeasUI applications, Tailwind CSS and the built-in recipe system are the recommended approach. CSS-in-JS is an optional choice when it fits the architecture of your application.

---

## Choosing a Styling Approach

| Approach         | Best for                                        |
| ---------------- | ----------------------------------------------- |
| `className`      | One-off customization and layout                |
| Semantic tokens  | Theme-aware colors and surfaces                 |
| BEM classes      | Reusable CSS overrides                          |
| State attributes | Interaction states                              |
| `tv()` recipes   | Reusable custom variants                        |
| CSS Modules      | Locally scoped CSS                              |
| Inline `style`   | Dynamic runtime values                          |
| CSS-in-JS        | Applications already using a CSS-in-JS solution |
